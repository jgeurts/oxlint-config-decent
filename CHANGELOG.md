## [5.0.0](https://github.com/jgeurts/oxlint-config-decent/compare/v4.2.38...v5.0.0) (2026-09-13)

### ⚠ BREAKING CHANGES

* The ESLint config export has been removed and the package is
  now published as oxlint-config-decent. The oxlint config is the root export;
  the ./oxlint subpath remains as a compatibility alias.

  - Remove the ESLint config (typescript-eslint caps TypeScript at <6.1.0,
    blocking TypeScript 7); the package is now oxlint-only with zero runtime
    dependencies
  - Migrate npm -> pnpm 11 (pnpm-lock.yaml, pnpm-workspace.yaml, packageManager
    pin, .pnpmfile.cjs for the JS-API TypeScript 6 shim the compat plugins need)
  - Replace unbuild with tsdown (dts generated by the native tsgo backend),
    the rules-parity script with vitest, prettier with oxfmt, and self-lint
    with oxlint dogfooding its own config
  - Move to TypeScript 7.0.2; CI matrix now Node 22/24/26
  - Release workflow uses a GitHub App token so semantic-release keeps pushing
    CHANGELOG.md updates to the protected main branch; drop npm audit signatures
    (near-zero coverage under pnpm's store layout); release from beta branch too

  * fix: harden release/CI workflows and document consumer setup

  - Pass NPM_TOKEN to semantic-release (required for the first publish of
    the renamed package; trusted publishing can be configured afterwards)
  - Fail CI and release if lint fixers change any files
  - Run lint scripts sequentially instead of concurrently
  - Add sideEffects:false and typesVersions for node10 ./oxlint resolution
  - README: eslint peer install note, eslint-plugin-react override, oxlint
    minimum 1.53.0, oxc-project/tsgolint URL, reactVersion/nextJsRootDir
  - Add docs/solutions entry for the TypeScript 7 JS-API shim
  - Ignore stray package-lock.json

  * fix: exclude pnpm-lock.yaml from super-linter

  codespell false-positives on lockfile hashes and the devlop package name;
  package-lock.json was skipped by codespell's defaults but pnpm-lock.yaml
  is not. Also drop the deprecated *_STANDARD validate variables.

  * refactor: consolidate toolchain onto Vite+ (vp) and restore custom rules

  - Move fmt/lint/test/pack/staged config into vite.config.ts (vite-plus,
    catalog-pinned like ldapts); delete .oxfmtrc.json, oxlint.config.ts,
    tsdown.config.ts; drop tsdown/vitest/oxfmt devDeps
  - Replace husky + lint-staged + pinst with vp staged and vp config-managed
    .vite-hooks
  - Restore require-extension and require-index as an oxlint JS plugin
    (oxlint-config-decent/plugin), enabled by default as decent/* rules
  - Replace the .pnpmfile.cjs TypeScript 7 shim with an explicit
    enableTypeScriptEstreePlugins option (default true); disabling drops the
    typescript-compat/vitest-compat/testing-library plugins until
    typescript-eslint supports TS7
  - Update tsconfig to nodenext/ES2023 with isolatedDeclarations for oxc dts
  - Build before lint in release.yml (self-referenced plugin loads from dist)
  - Renovate: group pnpm catalog updates with dev dependencies

  * feat: adopt TypeScript 6/7 side-by-side so estree compat plugins work on TS7

  Alias typescript to @typescript/typescript6 (official TS 6.0 JS API
  compatibility package) with tsc still provided by TypeScript 7 via the
  @typescript/native alias. typescript-compat, vitest-compat, and
  testing-library now load under TS7, so the repo dogfoods the full default
  config instead of the enableTypeScriptEstreePlugins: false opt-out (which
  remains available for consumers who prefer fewer dependencies).

  Add scripts/consumer-smoke-test.sh and a consumer_test CI job: installs the
  packed tarball in a fresh npm project with the side-by-side aliases and
  floating peer versions, then asserts through the real oxlint binary that the
  default config parses, a clean file passes, and the decent +
  typescript-compat rules fire.

  * Support NodeJS v22+
